# Repository guidance

- This phase contains documentation, registries, PyTorch references, validation helpers and an upstream submodule. Implement model algorithms only when a task authorizes implementation.
- Read the OP/kernel contract and independent reference before editing an operator. Keep `pymodel/ref` independent of `kernels/pto` and backend dispatch.
- Write reference calculations in execution order. Keep input checks, dtype casts, normalization and state initialization inline in each calculation path. Separate functions should represent meaningful operator or stage interfaces, rather than preparation-only wrappers such as `_prepare`.
- Follow `docs/kernel-organization.md`: the current phase has one complete logical kernel per OP, with matching OP-01/K-01 through OP-16/K-16 IDs. Keep sub-operations and recurrent/chunk or prefill/decode paths inside that entry; shared helpers are not additional kernels. Historical IDs are mapped in `data/legacy-kernel-map.json`.
- Read `docs/work-allocation.md` for A/B ownership, shared interfaces and delivery order. Keep shared definitions and their consumer examples in focused changes; update affected callers and tests together.
- The shared model and numerical baseline is `configs/models/qwen3_6_35b_a3b_fp8/`; read `baseline.json`, `numerics.json` and `docs/model-numerical-baseline.md` before implementing a reference. Preserve source cast boundaries and checkpoint scales; the pinned Transformers main model does not implement MTP.
- Use the confirmed `functional-v0.json` profile for Python functional validation, including activation quantization, BF16/FP32 tolerances, exact-output checks, TopK ties and expert bucketing. Declare per-output checks explicitly in each case; preserve the distinction between model-source facts and project conventions. The readable contract is `docs/functional-validation-v0.md`.
- PTO is pinned by `data/upstream.lock.json`. Read `third_party/pto-isa/AGENTS.md` when working inside the submodule; do not change upstream as a workaround for local input/layout mistakes.
- `data/operators.json` and `data/kernels.json` track owners and separate implementation/validation states. A file, catalog entry or placeholder is not implementation evidence.
- The functional phase uses hw-native-sys/pypto: `import pypto.language as pl`, `@pl.jit`, explicit Tile operations and native PTO C++ simulation (`hw_pto_cpp_sim`). Read `docs/pypto-a1.md` and the toolchain lock. Save PTO/C++/ELF evidence and fail on missing execution or numerical failures; never substitute TorchCodegen or golden. Distinguish C++ simulation from target hardware precision, NPU and LPU execution. Kernel factories use the operator name without a `_program` suffix.
- Keep each OP computation in execution order inside its JIT entry, using `pl.at` for native compilation scopes. Avoid single-use forwarding factories, local stage functions and recursive forwarding. Shape-specialization factories may return one JIT function; shared numerical primitives and independently tested recurrent/chunk algorithms may remain separate. Comments should explain formulas, tensor axes and dtype boundaries.
- Model outputs, routing indices, KV and GDN/Conv state are separately named and compared.
- GDN defaults to the native PTO C++ `bf16_carrier` path: FP8 bytes are decoded and activations quantized in the kernel, with BF16 carrying exact FP8 values. Record this separately from direct A5 FP8 instruction validation. Keep Token/head offsets and input state immutability in Prefill/Decode checks.
- Keep GDN recurrent and chunk as paths of K-06. Chunk coefficients, unit-lower solves and State products stay FP32; check multiple chunks, valid tails and chunk Prefill to recurrent Decode state handoff. A chunk loop around the recurrent Token update does not implement the chunk algorithm.
- LPUv2 instruction encoding, hardware buffer addresses and instruction width remain design inputs; do not copy an LPUv1 binary ABI into this project.
- Keep generated tensors, model weights, credentials, binaries and build outputs out of git.
- Run `python -m pytest tests/framework -q` when changing validation helpers. Framework fixtures do not validate model operators or PTO kernels; add their numerical and backend checks with the first actual implementation.
